# TaskFlow UI 与视觉规范

本文档定义页面路由、首页区域优先级布局，以及漫画风设计 token 与助手角色气泡规范。视觉方向参考《电器街的漫画店》的配色、漫画表现与热闹氛围，但**不复制官方角色或素材**，助手角色为原创。

设计北极星（PRD 第 2 节）：让用户随时回答"我现在最应该做什么"。因此 Next Task 区域优先级最高、装饰最克制；其余区域可漫画化、热闹。

---

## 1. 页面路由

桌面网页优先，使用客户端路由（React Router，hash 或 memory 模式，配合 Electron 本地加载）。

| 路由 | 页面 | 说明 |
| --- | --- | --- |
| `/` | 首页 Home | Next Task + 次级区域，见第 2 节 |
| `/projects` | 项目列表 | 项目卡片 + 进度 |
| `/projects/:id` | 项目详情 | 三级任务树、笔记、下一步、时间汇总 |
| `/timeline` | 时间轴 | 某日计划 vs 实际，`?date=` 切日期（见 2.6） |
| `/habits` | 习惯 | 打卡、连续、历史 |
| `/review` | 周复盘 | `?week=` 切换历史周、汇总、手填、下周重点（见 2.6） |
| `/import` | 智能导入 | 粘贴 -> 预览 -> 修正 -> 确认；入口也在首页底部 |
| `/settings` | 设置 | 导出/恢复、模块颜色、关于 |

导航：左侧漫画风侧边栏（分镜标签），或顶部工具栏。移动端仅保证基础可访问，不作第一版重点。

**任务没有自己的页面**：任务在它所在的清单里行内编辑，不占路由、不开抽屉（见第 3 节）。要定位某个任务时用 `?focus=<taskId>` 把光标送过去。

## 2. 首页布局（PRD 第 6 节）

严格按优先级自上而下。视觉重心永远是 Next Task。

```mermaid
flowchart TB
  Nav[侧边导航] --- Main
  subgraph Main [主区]
    NextTask[Next Task 主卡片 — 视觉中心, 克制装饰]
    subgraph Secondary [次级区域]
      Focus[今日三件事]
      Timeline[今日时间轴]
      Queue[今日队列 — 按项目分块, 展开子任务, 占满整行]
      Habits[习惯打卡]
      Quick[快速记录]
    end
    ImportEntry[智能导入入口 — 页面底部]
  end
  NextTask --> Secondary --> ImportEntry
```

### 2.1 Next Task 主卡片（PRD 6.1）

页面视觉中心，一次只突出一项任务。展示：

- 任务名称（大字号）
- 所属项目与模块（模块用其配色小标签）
- 与哪项"今日三件事"相关
- 已累计投入时间
- 操作按钮：`开始计时`、`完成`、`换一个`、`查看上下文`

数据来自 `tasks.getNext`。完成后立即请求下一项并动画切换。此卡片保持清晰，避免网点/速度线等装饰干扰执行——装饰只出现在卡片外围或次级区域。

`换一个` 调 `tasks.getNext({ excludeTaskId })`；助手角色气泡展示 `reason.message`（见第 5 节），让推荐可解释但不弹窗、不强制。

`查看上下文` 跳到这件事在项目大纲里的位置并把光标放进那一行（`?focus=<taskId>`，见 3.5）：卡片本身只放执行所需的最少信息，要看它拆成了什么、旁边还有什么，去大纲里看。

### 2.2 次级区域

按 PRD 6.3 顺序排列，均为分镜式卡片：

1. 今日三件事（`focus.getDay`）：三个槽，可编辑、关联项目/任务、勾选完成；点已关联的任务把光标送到它在大纲里的那一行（见 3.5）。每槽是行内输入框，失焦或 Enter 提交 `focus.set`（按 `date + slot` upsert），Esc 撤销本次编辑。左侧的黄色序号圆圈兼作勾选按钮，悬停时序号变 `✓`，达成后文字加粗并划线——保持黑色而不置灰，达成是成果不是废弃。空槽的圆圈禁用（先写下结果才谈达成），清空内容会一并重置完成状态。三件全部达成时在卡片右下角盖一枚 `Mission Clear` 橡皮章（见 6.2）。
2. 今日时间轴（`stats.timeline`）：计划 vs 实际，见第 4 节渲染区分。
3. 今日队列（`today.list`）：首页的主力清单，按项目分块并展开到子任务，见 2.3。
4. 习惯打卡（`habits.list`）：今日状态一键打卡。
5. 快速记录（`notes.quickCapture`）：随手记想法/问题。

队列按天归属（见 2.3），所以回看历史日期时它照样显示那天的队列。习惯打卡与快速记录只有「今天」一种状态，非今日隐藏。

### 2.3 今日队列（按天归属 + 按项目分块 + 展开子任务）

**没有独立的「项目进度」区域**。项目不是首页上另一件要单独关心的事，它就是今天要干的活的归属；把进度条单列出来，用户得在两个区域之间对照才知道「这个项目今天要做什么」。所以项目直接以分块形式进入今日队列：属于同一项目的任务聚成一块，块头写项目名，不属于任何项目的散任务归入最后一类「零散任务」块。想看进度去 `/projects`。

队列展开到**子任务层级**：一件事拆开是什么样，应该在首页就看得见。因此队列行会连同它的整棵后代树一起渲染，并且可以就地敲字、加行、改层级（第 3 节）。

队列**按天归属**（data-model 1.1）：某天的画面里有什么，取决于那天 `today_entries` 里有哪些行，因此每一天的队列都能精确还原，跟着 `?date=` 一起回看。

- **块头**：项目默认模块的色点 + 项目名（链接到 `/projects/:id`）+ 右侧计数 `N 项待做 · 达成 M`。**块头不放进度条**——进度是项目视角的指标，首页只关心今天。「零散任务」块无色点、无链接。
- **块的顺序**：按块内未达成任务里最靠前的队列序，用户的手动排序仍然说了算；整块做完的沉到最后。散任务块没有固定位置，同样参与排序。
- **哪些行会出现**：那天在队列里、且祖先那天都不在队列的任务作为根行。父子同时入队时只保留父级，避免同一件事出现两次。后代跟着展开，但**已完成的后代只在它完成的那天出现**——于是顺延一个「子任务做了一半」的父任务时，昨天做完的子任务留在昨天，今天只剩没做完的分支。
- **层级表达**：子行缩进，靠左侧一条竖线连回父行；字号略小、去掉分镜描边，读起来是「父任务内部的清单」而不是并列的队列项。
- **每行的操作**（根行与子行一致）：左侧模块色圆点即勾选按钮，点一下完成（`tasks.complete`），再点一下恢复（`tasks.reopen`）；标题是行内输入框，点进去直接改（第 3 节）。行尾的操作槽随日期变化：今天的行浮出黑色加粗箭头 `→` 设为 Next Task（`tasks.pinNext`），回看过去某天时换成 `↷` 把这件事顺延到今天（`today.carryOver`）。已完成的行两者都不给，但保留等宽占位以对齐行尾；槽位常驻占位、仅切换可见性，避免行内文字抖动。
- **行内注记**：顺延来的行挂一个黄色「顺延」小标签，`title` 说明它最早是哪天进队列的；那天终究没做完、后来才完成的行（`done_later`）在标题后写「当天没做完 · X 月 X 日才完成」，如实呈现而不伪装成当天的成果。
- **达成的任务沉到块末尾而不是消失**：底色转 `--bg-panel-alt`、文字加粗划线但保持黑色（同 6.2 的达成即成果），那天干掉的事一直看得见。只有根行沉底，**子行按 `sort_order` 保持原位**——子任务表达的是任务的结构，顺序一变就不好读了。
- **计数口径**：块头与面板头的计数覆盖块内展示出来的每个节点，含被父任务带出的子任务。`done_later` 计入「没做完」那一侧——那天它确实没做完。
- 队列横向占满整行（两列栅格里 `col-span-2`），否则展开后的标题会被挤成两行。
- 拖拽排序与右键日终操作（推迟/放回/放弃/拆分/完成）作用于根行。

### 2.4 遗留与一键顺延

**跨天什么都不会自动发生。** 没做完的事留在它原本那一天，第二天的队列天然是空的——系统不替用户把旧账搬到今天（PRD 5.4）。但欠账必须被看见，否则"不自动"就等于"忘掉"。所以今天的首页在 Next Task 卡片下方放一条虚线边框的提示条：

- 数据来自 `today.backlog({ before: 今天 })`：早于今天入过队、至今未完成、且今天还没有行的任务。已完成的、已经顺延过来的都不算欠账。
- 文案给出规模与年龄：`还有 N 项没做完`，加一句「最久的一项从 X 天前拖到现在」或「来自昨天」。看见"从 4 天前拖到现在"比看见一个数字更容易让人做决定。
- 两个按钮：`看看是哪些` 展开清单（每项带模块色点、项目名、最早入队日期，以及只顺延这一项的 `↷`）；`全部顺延到今天` 一次带走全部。
- **无遗留时整条不渲染**：没有欠账的早晨不该被提醒有欠账。
- 只在今天出现。回看过去某天时该做的是逐行顺延（见 2.3 的行尾操作），而不是在历史页面上再问一次"要不要带到今天"。

顺延是 INSERT 而不是 MOVE：今天多一行，昨天那行不动。所以顺延过之后回看昨天，那件事仍然在昨天的队列里显示为「当天没做完」，历史不会被今天的动作改写。

### 2.5 智能导入入口

置于页面底部（PRD 11：后续按使用频率再调位置）。点击进入 `/import`。

### 2.6 日期切换与回看

首页默认停在今天，顶栏右侧的日期切换器可以回看任意一天的记录（PRD 14.10：任意日期都能补写和查看）。

- **状态载体**：查询参数 `?date=YYYY-MM-DD`，与定位任务的 `?focus=` 同一套做法——浏览器前进/后退可切、刷新能恢复、链接可复制。参数缺失或不合法都回落到今天，于是 `/` 永远是今天；切回今天时删掉参数而不是写上今天的日期，避免留下一条明天就指向昨天的链接。
- **控件**：`←` 前一天 / 中间的日期标签 / `→` 后一天 / 偏离今天时才出现的 `回到今天`。日期标签上叠一个透明的原生日期选择器，点一下能跳到任意一天，而显示的仍是中文日期而不是浏览器默认格式；近三天额外挂一个「今天 / 昨天 / 前天 / 明天」的口语标签，一眼知道自己在哪。
- **跟着日期走的区域**：当日三件事（`focus.getDay`，历史日期照样可编辑）、当日时间轴（`stats.timeline`）、当日队列（`today.list`，队列按天归属所以能精确还原那天的清单，见 2.3）。换天时三件事的输入行整行重挂，未提交的草稿不会漂到另一天。
- **回看时隐藏的区域**：习惯打卡、快速记录——它们只有「今天」一种状态。遗留提示条（2.4）也只在今天出现。
- **Next Task 主卡片**在回看时整块换成**当日汇总卡片**：助手气泡一句话说清那天投入了多久、几段记录，下面按模块列出时间分布，并常驻 `回到今天` 出口——「现在最该做什么」只对今天成立，回看时留着那张卡片只会误导。汇总由时间轴的 `actual` 在前端算出，不新增 IPC 频道。未来日期只有计划轨有内容，文案相应改成提示「这天还没到」。

时间轴页 `/timeline` 复用同一个控件与同一个 `?date=` 参数，所以首页时间轴卡片的 `展开 →` 会把当前日期一起带过去。周复盘页 `/review` 用同形状的控件切换历史周，参数是 `?week=`，一律规范化到该周周一（PRD 12：复盘归属被复盘的自然周，而不是填写日期）。

日期一律按**本地时区**格式化为 `YYYY-MM-DD`（`src/renderer/lib/date.ts`）。不能用 `toISOString().slice(0, 10)`：那是 UTC 日期，东八区凌晨会算成前一天，「今天」在半夜就错了。

## 3. 任务的行内大纲编辑

**没有任务详情页，也没有抽屉或弹窗。** 任务就在它所在的那份清单里直接敲——回车加一行，Tab 决定层级，Shift+Enter 补一句描述。写任务这件事本身必须快到不用想，任何需要「先打开某个界面」的设计都会拖慢它。

### 3.1 键位

| 按键 | 行为 |
| --- | --- |
| `Enter` | 在当前行下面插入一个**同级**任务，光标直接落进去 |
| `Tab` | 缩进一级：成为上一个同级任务的子任务，并继承它的项目与模块 |
| `⌫`（行首）| 退一级；已经是第一级且这行是空的就删掉它 |
| `Shift+Tab` | 同样退一级 |
| `Shift+Enter` | 给当前任务写描述（落成一条备注），光标进描述框 |
| `↑` / `↓` | 在行间移动光标 |
| `Esc` | 撤销这一行本次未提交的编辑并失焦 |

描述框里 `Enter` 表示写完、光标回到任务行，`Shift+Enter` 才是换行；描述清空后失焦即删除这条备注。

### 3.2 层级规则

- 最深三级（PRD 4.3）。`Tab` 会连同这行的整棵后代一起下移，因此判定条件是「当前层级 + 子树高度 ≤ 3」，而不是只看自己。
- 上面没有同级任务时 `Tab` 无效——没有可挂靠的父级。
- 被拦下时不弹窗、不报错，只把键位提示行换成一句话（「最多三级，再往下的内容适合写成描述」），两秒后复原。第四层内容的正确去处是描述，这与 PRD 11「第四层及更深的粘贴内容识别为备注」是同一条规则。
- 缩进后继承新父级的项目与模块（PRD 4.1：项目内任务自动继承）。

### 3.3 描述与批注是两回事

`Shift+Enter` 写的内容进 `tasks.description`：一个任务一段描述，`Enter` 提交、清空即清掉。它不是 `notes`——批注（`note`/`idea`/`question`/`link`）是随手记下的碎片，可以有很多条、能转成任务；描述是这件事本身的说明，只有一份。

描述用手写批注样式呈现（虚线框、微倾斜、字号略小），与任务行明显不同——它不进待办统计，也不参与进度计算。

### 3.3.1 新行的占位标题

后端 `createTaskInput` 要求 `title` 至少一个字符，所以 `Enter` 出来的新行带占位标题「新任务」，并且**以全选状态获得焦点**——第一个按键就把它替换掉，手感与空行无异。行首 `⌫` 判定「这行是空的」时把「还是占位标题」也算进去，于是误加的行退格一下就没了。

### 3.4 用在哪里

两处共用**行为**而不是共用外观：键位、层级判定、保存时机都在 `useOutlineKeys` 里，视觉各自保留。

| 位置 | 说明 |
| --- | --- |
| 项目详情 `/projects/:id` | 主场，用默认的 `TaskOutline` 外观。三级结构在这里才有意义，项目的任务树就是一份大纲 |
| 首页今日队列 | 保留 2.3 的分块、竖线、行尾操作，只把标题换成输入框 |

队列里两条额外规则：

- **只有今天能就地编辑**。回看历史某天时标题退回按钮，点它跳到项目大纲里改——往过去某天的队列里加行没有意义。
- **跨块不能互相缩进**。队列按项目分块，若允许 `Tab` 把 A 项目的任务挂到 B 项目的任务下，一次误触就换了项目。所以缩进只在同一块内成立。

### 3.5 定位到某个任务

任务没有详情页，所谓「上下文」就是它在项目大纲里的位置。`?focus=<taskId>` 承载这件事：大纲读到这个参数就滚动到那一行、把光标放进标题框，然后清掉参数（只聚焦一次，避免刷新或后退时又跳一次）。

- 首页 Next Task 卡片的 `查看上下文`：有项目就跳 `/projects/:id?focus=<taskId>`，散任务就在首页队列里就地聚焦。
- 首页队列行、三件事里已关联的任务：同一个机制。

### 3.6 保存与失败

- **没有保存按钮**。标题在失焦、`Enter`、`Tab`、`↑↓` 移开时提交 `tasks.update`；描述在失焦或 `Enter` 时提交。
- **清空标题不算重命名**，输入框回滚成原文。宁可留着原来的标题，也不要一个手滑把行变成空白。
- 输入框走非受控 + 直接读 DOM 值：大纲可能有几十行，每敲一个字都重渲染整棵树会卡。
- 任何写操作后统一失效 `queries.ts` 里的 `TASK_SCOPE`——改层级会牵动项目进度、推荐结果与队列分块，挑着失效容易漏。
- `Enter` 是两步：`tasks.create` 把新行放到同级末尾，再 `tasks.move({ position })` 摆到当前行下面。`createTaskInput` 没有插入位参数，所以位置由第二步负责。

## 4. 时间轴渲染（计划 vs 实际）

同一时间轴上必须视觉区分两类数据（PRD 第 7 节）：

- **计划**（`schedule_events`）：描边/虚线块、半透明、置于轨道背景层。
- **实际**（`time_entries`）：实心漫画分镜块，`source=manual`（手动补录）用斜纹网点区分于 `timer`。
- 正在计时的段用动态速度线/呼吸动画提示"进行中"。
- 跨午夜区间已由领域层按天切分（`stats.timeline` 返回切好的数据），前端直接渲染当天片段。
- 渲染哪一天由 `?date=` 决定（见 2.6），刻度原点跟着那天的 00:00 走，否则回看昨天会把块画到轨道外。未结束的段只可能属于今天，历史日期的未结束段截到当天可见范围末尾。
- 那天既无计划也无计时记录时，图例换成一行说明而不是留着三个对不上任何色块的图例。

## 5. 助手角色（原创）与气泡规范

一个全局原创助手角色，贯穿全应用，提供推荐原因与轻量反馈。

- **角色**：原创设定，不复制任何现有作品角色。固定停靠首页 Next Task 卡片附近。
- **气泡内容来源**：
  - 推荐理由：`tasks.getNext` 返回的 `reason.message`（如"你已连续完成 5 项工作任务，要不要换个运动任务喘口气？"对应 `rule: module_balance`）。
  - 完成反馈：任务完成时的漫画式祝贺气泡。
  - 空状态引导：无可执行任务、队列为空时的轻量提示。
  - 励志轮换：静置时每 9 秒换一条可爱励志短句（`useAssistantMessage`），先显示推荐理由再进入轮换；理由变化时重新从理由开始，保证新推荐一定被看到。
- **气泡形状**：尖角朝左，指向左侧的助手角色；角色与气泡垂直居中对齐。
- **约束**：气泡是被动展示，**不弹窗、不打断、不强制**。模块平衡类推荐只建议不逼迫（PRD 6.2）。轮换只换文案，不带声音与位移，`prefers-reduced-motion` 下不做动画。
- **理由到文案的映射**（rule -> 气泡语气基调）：

| reason.rule | 气泡基调示例 |
| --- | --- |
| `active_timer` | "这个还在计时中，继续吧" |
| `focus_linked` | "这关系到你今天想要的成果之一" |
| `in_progress` | "这件已经开了头，收个尾？" |
| `project_next_action` | "这是 XX 项目的下一步" |
| `today_queue_top` | "你把它排在了队列最前面" |
| `module_balance` | "连续工作有一会儿了，换个别的模块？" |

## 6. 设计 token（Tailwind 主题承载）

在 `tailwind.config` 的 `theme.extend` 中定义，组件只引用语义 token，不写死色值。

### 6.1 配色

明亮、高饱和但可长时间使用（PRD 13）。

```
--bg-base        纸张米白 / 浅色画布
--bg-panel       分镜卡片底色（略暖白）
--ink            主文字（近黑墨色，非纯黑）
--ink-soft       次要文字
--line           分镜描边（粗黑线）
--accent         主强调（招牌高饱和色，用于 Next Task 焦点、主按钮）
--accent-soft    强调的浅色态
--halftone       网点色（低透明度点阵）
```

模块配色（8 个，来自 `modules.color`，用于标签与时间轴块）：工作/兴趣/个人提升/运动/饮食/支出/人际/其他各一高饱和色，彼此可区分且在浅背景上清晰。

### 6.2 漫画表现元素

- **分镜卡片**：粗黑描边（`--line`）、轻微不规则圆角或直角、可选投影，模拟漫画格。
- **网点（halftone）**：用于卡片背景/强调区域的点阵纹理，低透明度，避免干扰文字。
- **速度线**：用于"进行中计时""换一个"等动作反馈的方向性线条动画。
- **手写批注**：notes（想法/问题/链接）以角色气泡、手写体批注样式呈现，明确区别于待办统计。
- **完成动画**：任务完成时的漫画式反馈（如"达成"拟声词 + 分镜闪现），短促、不阻塞下一步推荐。
- **橡皮章（`.stamp`）**：达成整组目标时盖在卡片上的双线描边斜章，`accent` 色 + `mix-blend-mode: multiply` 与下方文字叠印，落章动画由大砸小回弹。纯装饰（`aria-hidden`）且 `pointer-events: none`，同样的信息必须另有文字承载（如"3 / 3 达成"）。

### 6.3 排版与密度

- 标题用略带漫画感的显示字体，正文用高可读性无衬线体。
- Next Task 区域低密度、大留白、大字号；次级区域可较密、热闹。
- 长时间使用友好：避免纯白刺眼背景、避免过强对比闪烁动画。

### 6.4 无障碍与降级

- 颜色不作为唯一区分手段：模块标签同时带文字/图标；计划 vs 实际除颜色外用描边/网点区分。
- 提供"减少动画"设置项（尊重系统 `prefers-reduced-motion`），完成动画与速度线可关闭。

## 7. 状态与交互约定

- 所有数据经 TanStack Query，mutation 成功后 invalidate 相关 query（写后刷新）。
- 乐观更新仅用于高频轻操作（打卡、队列排序、勾选完成）；其余用加载态。
- 错误按 `IpcResult.error.code` 映射为漫画风 toast/气泡，不打断当前任务执行流。
- 空状态（无项目/无任务/队列空/无复盘）均由助手角色给出引导文案，保持热闹不冷场。
